# 데이터 정제와 최적화 정식화

데이터를 확인하고 정제한 뒤 문제를 글로 정식화하고, 단순 기준선에서 시작해 알고리즘을 고르고 숫자로 검증한다. 공식 규칙·과제 지시가 이 Skill보다 우선한다. 목적·제약·가중치 같은 업무 결정은 참가자와 업무 담당자가 소유한다. 아래 도구는 범용 구성 요소이며 어떤 과제의 완성 답안도 아니다.

## 1. 프로파일링 (값을 눈으로 계산하지 않는다)

- data-profiling Skill이 있으면 그 흐름을 따른다. 전체 소스가 있으면 `python3 .hackathon-kit/tools/audit_csv.py data.csv --required a,b --unique id`를 필요할 때만 쓴다. 셸 명령의 `.hackathon-kit/` 부분은 키트 위치에 맞게 바꾼다.
- 확인 항목: 스키마(열·형식), 행 단위(한 행이 무엇인지), 결측, 중복, 형식·단위 혼재(분/시간, 원/천원, 날짜 형식), 이상치, 규모 n·m.
- 건수는 분모와 함께 적는다. 예: `duration 결측 3/120행`.

## 2. 정제

- 원본 파일은 바꾸지 않는다. 정제는 코드로 재현 가능하게 하고 규칙별 영향 건수를 로그로 남긴다.
- 결과를 바꾸는 애매한 정제는 담당자에게 구체적으로 묻는다. 예: "이름과 부서가 같고 이메일이 다른 2건을 같은 사람으로 볼까요?", "소요시간 결측 3건은 (a) 제외, (b) 같은 유형 중앙값으로 채움 중 어느 쪽인가요?" 질문 하나에 사실 하나·물음표 하나로 쓰고, 사람 담당자에게는 2~3개씩, 구체 질문에만 답하는 무제한 담당자 에이전트에게는 질문 하나에 사실 하나로 모두 묻는다. 전송 단위는 반응을 보고 정한다.
- 중복 판정 키, 결측 대체, 단위 환산, 이상치 제외는 답을 받기 전 임시 가정으로 표시하고, 답을 받으면 결정으로 바꿔 기록한다.

## 3. 정식화 카드 (구현 전에 한 장)

| 항목 | 적을 내용 |
|---|---|
| 결정 변수 | 무엇을 정하나 (예: 수강생 i를 강좌 j에 배정) |
| 목적 | 단일 / 가중합(가중치 출처) / 사전식(1순위 먼저, 동률이면 2순위) |
| 하드 제약 | 절대 어기면 안 됨 (정원, 예산, 겹침 금지) → 위반 0건 검사 |
| 소프트 제약 | 어기면 벌점 (선호, 균형) → 벌점 크기를 담당자와 확인 |
| 규모·시간 | n, m, 허용 응답 시간 |
| 동점 처리 | 같은 목적값일 때 고르는 규칙 (결정성 확보) |

하드 제약을 목적의 벌점으로만 섞지 않는다. 섞었다면 결과에서 위반 건수를 따로 센다.

## 4. 유형 판별과 후보

| 유형 | 단순 기준선 | 개선·정확해 |
|---|---|---|
| 배정·매칭 | 비용 오름차순 탐욕 | 헝가리안(1:1), 정원은 열 복제 후 헝가리안 또는 탐욕+교환, 행당 여러 개·그룹 제약은 최소비용 유량, 소규모 완전탐색 |
| 선택·예산 | 가치/비용 비율 탐욕 | 0/1 배낭 DP (정수 단위) |
| 적재·묶음 | FFD(큰 것부터 첫 칸). 한도가 여러 개이거나 함께 담기 금지가 있으면 `first_fit_multi` | 하한(`bins_lower_bound`)과 비교, 넣는 순서를 바꾸는 담금질, 소규모 완전탐색. 결과는 `pack_report`로 위반·묶음 분리 확인 |
| 일정·구간 | 우선순위 규칙(마감 빠른 순 등) | 구간 스케줄링(끝 빠른 순), 국소 탐색 |
| 방문·작업 순서 | 최근접 이웃 | 2-opt, n≤9 완전탐색, 담금질 |
| 최단 경로(작업 단계 그래프) | 다익스트라(음수 없음) | 음수 간선이면 다른 방법 필요 |
| 군집·묶기 | 용량 고려 탐욕 | 간단 k-means(seed 고정) 후 용량 보정 |
| 다목적 | 가중합 | 사전식, 파레토 후보 몇 개를 담당자에게 제시 |

정확해(작을 때 보장), 휴리스틱(빠르고 설명 쉬움), 메타휴리스틱(국소 탐색·담금질, seed 필요), 라이브러리(scipy·ortools·pulp·networkx)는 **이미 설치·허용된 경우에만** 고른다. 설치 여부는 `python3 -c "import scipy"`처럼 읽기만 확인하고 설치하지 않는다. 없으면 표준 라이브러리 구현(전체 소스의 ../../../tools/opt_kit.py 등)이나 직접 작성한 작은 함수로 대신한다.

배정 제약 모델링: 정원 합이 행 수보다 작으면 미배정 더미 열을 허용한다(`hungarian_with_capacity(..., allow_unassigned=True, unassigned_cost=u)`, u는 담당자가 정할 "비워 둠" 비용). `allow_unassigned=True`에서 u를 빼면 오류가 난다. 0 이상 비용을 최소화할 때 u=0이면 "비워 둠"이 가장 싸서 아무도 배정되지 않기 때문이다. u는 받아들일 수 있는 가장 큰 비용보다 크게 정한다. 배정하면 안 되는 칸은 `forbidden={(행, 열)}`로 막고(최대화에서 그런 칸을 0점으로만 두면 `unassigned_cost=0`과 동점이라 배정될 수 있다), 큰 비용을 직접 넣었다면 결과에서 금지 칸 사용 건수를 따로 센다. 점수 최대화는 점수를 음수로 바꾼 비용 최소화다. 행당 최대 k개, (행, 그룹)당 1개(예: 같은 시간대), 열 정원이 함께 있으면 헝가리안 행렬로는 표현할 수 없으므로 `assignment_flow(scores, k, caps, groups=..., maximize=True)`(최소비용 유량)로 정확히 풀고 `constraint_report(..., row_limits=k, groups=...)`로 위반 0건을 확인한다. 미리 확정된 배정(고정 배정)이 있으면 먼저 사전 처리한다. 고정 배정마다 그 열의 정원을 1 줄이고, 그 행의 한도를 1 줄이고, 같은 그룹의 열을 그 행에 금지하고, 고정 배정 점수는 따로 합산한다. 사전 처리 뒤 정원이나 한도가 음수가 되면 풀지 말고 충돌 목록으로 담당자에게 보고한다. `assignment_flow(..., fixed=[(행, 열), ...])`가 같은 절차를 안에서 수행하고, 충돌이 있으면 풀지 않은 채 `conflicts` 목록을 돌려준다(오류 대신 목록이라 충돌을 한 번에 모아 보고할 수 있다). 사전식 동점은 "점수×1000" 같은 임의 가중치 대신, 정수 1순위 비용에 보조 키(정수)를 작은 단위 ε로 더한다. 점수를 최대화할 때(`maximize=True`)는 보조 키가 작은 쪽이 이기도록 점수에서 ε×보조 키를 **뺀다**. 조건은 ε × (보조 키 합의 최댓값) < 1순위 비용의 최소 차이다. 이 방법은 보조 키의 합만 줄이므로 특정 두 사람의 순서 역전이 없다고 보장하지 않는다. 엄격한 순서가 필요하면 1순위 최적값을 제약으로 고정하고 2순위를 다시 푼다.

## 5. 선택 기준

규모·시간 제한·설명 가능성·결정성·구현 시간·검증 용이성을 비교한다. 해커톤 기본값은 **단순 기준선 먼저 → 개선 → 소규모에서 정확해와 비교**다. 기준선이 요구 품질을 이미 만족하면 더 복잡하게 만들지 않는다.

## 6. 검증 지표

- 하드 제약 위반 0건 (정원 초과, 예산 초과, 겹침)
- 목적값과 기준선 대비 개선량
- 소규모 표본에서 정확해와의 차이(gap)
- 실행 시간 (실제 입력 규모에서 측정)
- 난수를 쓰면 seed 여러 개에서 결과 범위
- 역할별 지표 (예: 이용자 만족도, 운영자 비용·작업량)

측정하지 않은 항목은 NOT_RUN으로 적는다. 기준선과 비교하지 않은 결과를 '최적'이라 부르지 않는다.

## 7. 설명
