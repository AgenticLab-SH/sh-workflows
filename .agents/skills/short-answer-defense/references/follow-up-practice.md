# 깊이별 꼬리질문 사전 연습

공식 기출이나 실제 시험 답안이 아닌 자체 연습이다. 실제 AI 금지 단계에는 시작·계속하지 않는다.

## 혼자 시작할 때

실제 평가가 아닌 준비 환경에서 작은 완료 기능 하나를 고른다. 해설을 닫고 자신의 말로 먼저 답한 뒤, 실제 파일·관측과 대조한다. 약한 연결 하나만 학습하고 다른 입력으로 예상한다. 전체 소스가 있으면 [합성 연결 연습](../../../../docs/METHOD_TO_EXPLANATION.md)을 쓴다. 사용자가 답하지 않았다면 이해 점검은 미실시이며 대신 답변하거나 연습 점수를 만들지 않는다.

## 준비할 근거

실제 완료한 작은 기능 하나의 요구·결정·입력→처리→출력·파일/함수·관측 결과·한계를 확인한다. 이해를 위한 교육 설명과 제한 시간 자가 답변을 구분한다. 기능이 아직 없다면 합성 연습 과제임을 밝힌다.

## 질문을 한 단계씩 깊게

1. 사용자: 누구의 어떤 판단·반복작업을 줄이는가? 완료를 무엇으로 판단하는가?
2. 흐름: 합성 입력 한 건을 따라가면 어떤 검증·변환·선택을 거쳐 출력되는가?
3. 이유: 왜 그 규칙/자료구조/알고리즘인가? 비교 후보와 선택을 바꿀 조건은?
4. 근거: 어떤 원문·담당자 답이 어떤 구현을 바꿨나? 가정을 사실로 말한 부분은 없나?
5. 경계: 결측·중복·단위 차이·동점·충돌·불가능 입력에서 실제로 어떻게 동작하나?
6. 반례: 입력 규모가 커지거나 규칙 하나가 바뀌면 어디가 먼저 실패하나? 최적성·속도·비용 중 무엇을 보장하지 못하나?
7. 관측: 실제 실행한 사례의 기대·결과는? 실행하지 않은 검사를 구분할 수 있나?

모두 나열해 답하도록 하지 않는다. 현재 답에서 가장 약한 연결 하나를 골라 후속 질문을 낸다. 용어를 몰라 막히면 사전 교육 단계에서만 쉬운 말·작은 예로 설명하고 다른 예를 본인이 풀게 한다. 함수명 암기 대신 동작과 근거를 우선하되 실제 없는 구현을 주장하지 않게 한다.

## 피드백과 종료

답변 뒤 사실 일치 / 원인 설명 / 구체 근거 / 한계 구분을 각각 확인·부분·미확인으로 기록한다. 근거 없는 “잘했다”나 가상의 점수를 쓰지 않는다. 틀린 전제 하나와 다음 학습 하나만 돌려준다. 시간 제한·AI 없는 자가 답변에서는 답변 중 코칭하지 않는다.

이해 점검: 설명한 합성 사례와 다른 입력으로 결과를 예상하고 이유를 말할 수 있는가? 못하면 해당 지식 공백으로 되돌린다. 반복해서 이해한 부분은 재질문하지 않는다. 공식 시험 방식·시간을 이 연습이 정하지 않는다.
