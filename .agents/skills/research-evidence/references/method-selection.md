# 방법 채택 카드

새 과제에 재사용하는 사전 준비 절차다. 실제 과제 자료·시험 경험은 공개 키트에 넣지 않는다. 외부 검색이 금지된 환경에서는 허용된 내장 자료만 쓰고 부족한 근거를 표시한다.

## 문제를 먼저 고정

입력 필드·단위·결측/중복·규모 / 정할 값 / 목적 / 하드·소프트 제약 / 동점 / 시간·메모리 / 설치·네트워크 제한을 짧게 적는다. 미확정 업무 규칙은 담당자 질문으로 보낸다. 최적화 과제는 optimization-modeling의 정식화 카드를 재사용한다.

## 필요한 근거만 획득

- 주장 하나에 이를 확인할 1차 자료 하나를 우선한다. 논문 원문, 공식 구현·문서에서 해당 가정·정리·제약·라이선스·버전을 읽는다. 초록·검색 결과만으로 채택하지 않는다.
- 논문 문제와 현재 문제의 차이(입력, 목적, 제약, 규모)를 적는다. 유명함이나 논문 점수가 현재 데이터의 개선을 보장하지 않는다.
- 외부 검색에는 일반화한 기술 질문만 보낸다. 실제 과제 문장·데이터·식별자·화면·코드는 보내지 않는다.
- 원문을 읽지 못했으면 후보/미확인으로 두고, 확인된 자료나 설명 가능한 기준선을 사용한다.

## 비교는 작은 표 하나

| 후보 | 이 문제의 전제·제약 충족 | 기대 이점·보장 범위 | 시간·메모리·구현 비용 | 검증 방법 | 근거 |
|---|---|---|---|---|---|
| 단순 기준선 | 확인/미확정 | 관측 전 수치 금지 | 현재 환경 기준 | 정상·경계·불가능 사례 | 문서/코드 위치 |
| 개선 후보(필요한 것만) | 일치/불일치 | 정확해/근사/휴리스틱 구분 | 제한 내 여부 | 같은 입력으로 비교 | 원문 URL·제목·절·버전 |

선택: 무엇 / 왜 현재 조건에 맞는가 / 다른 후보를 안 쓴 이유 / 언제 재검토하는가. 실제 실행 전에는 속도·품질을 예상으로 표시한다. 제약 위반, 목적값, 실행 시간과 재현성을 같은 조건에서 비교하고 측정하지 않은 것은 NOT_RUN으로 둔다. 작은 정확해와 비교하더라도 큰 입력의 최적성을 주장하지 않는다.

## 이해 확인과 영구 기록

사용자가 개발을 몰라도 입력 한 건이 어떤 규칙을 거쳐 결과가 되는지 설명한다. 수식은 각 기호의 뜻과 작은 합성 예제로 연결한다. 사용자가 직접 “어떤 조건에서 이 선택이 실패하는가?”를 설명하게 하고, 답하지 못한 부분만 다시 가르친다.

허용된 작업 정본의 기존 출처/결정 기록에 출처 URL·제목·확인일·해당 절·채택한 내용·현재 코드 위치·라이선스·미확인을 남긴다. 공개 준비 키트에 실제 과제별 기록을 커밋하지 않는다. 확인하지 않은 URL이나 논문을 만들어 채우지 않는다.

전체 소스가 있을 때만 [합성 연결 예제](../../../../docs/METHOD_TO_EXPLANATION.md)로 질문ID→결정→함수→관측→설명을 연습한다. 개별 Skill만 있으면 위 카드와 허용된 현재 작업 기록으로 진행하며 없는 키트 파일을 찾느라 멈추지 않는다.
