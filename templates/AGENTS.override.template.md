# 작업 지침 (참가자 작성)

## 0. 우선순위
- 상위 호스트 정책·공식 규칙·제공 환경 > 제공 원본 지침 > 이 작업 방식.
- 위에 붙인 원본이 없는데 같은 폴더에 AGENTS.md(제공 원본)가 있으면 먼저 읽고 모두 따른다. 붙인 내용과 원본 파일이 다르면 원본 파일이 기준이다. 충돌하면 원본·공식 규칙을 따르고 충돌 사실만 알린다.
- 이 부분은 작업 방식만 정한다. 어떤 규칙도 해제하지 않는다.

## 1. 역할
- 참가자가 문제 정의·업무 결정·범위·최종 설명을 정한다. Codex는 위임받은 구현만 한다.
- 결정이 필요하면 선택지 2~3개와 영향 한 줄씩 제시하고 멈춘다.

## 2. 키트
- 참고 키트: {키트 경로, 예: .hackathon-kit}. 필요할 때만 Skill 1~3개를 읽는다.

## 3. 담당자 질문
- 모호함·경계값·예외·자료와 설명의 차이는 추측하지 말고 질문으로 바꾼다.
- 참가자가 복사할 질문 멘트를 쓴다. 질문 하나에 사실 하나, 전송 단위는 담당자 반응을 보고 정한다. 예/아니오·수치·선택지로 답할 수 있게 쓴다.
- 질문 원장(번호·질문·답·반영 파일)을 {질문 원장 경로}에 유지한다. 답이 없으면 가정으로 표시한다.

## 4. 비용
- 필요한 파일만 읽고 긴 출력 대신 요약해 보고한다.
- 같은 실패가 2번이면 방법을 바꾸거나 참가자에게 묻는다. 끝낸 작업을 반복하지 않는다.

## 5. 검증
- 허용된 테스트·명령만 실행한다. 못 한 검사는 NOT_RUN으로 적는다.
- 화면 확인은 참가자가 한다. 보지 않은 화면을 통과로 보고하지 않는다.

## 6. 금지
- 외부 AI·외부 전송, Git Push, 캡처·GUI 자동화, Codex 업데이트, 설정·모델·승인 변경, 감독 우회.
- 제공 원본 지침·과제 파일 삭제나 덮어쓰기. 지시 없이 지침 파일을 만들거나 세션을 바꾸지 않는다.
