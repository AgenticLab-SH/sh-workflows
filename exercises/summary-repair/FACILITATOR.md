# 모의 C 진행자 자료

먼저 질문과 기대값을 적은 뒤 읽습니다. 자체 제작 규칙이며 아래 수치는 **수작업으로 정한 기대값**입니다. 실행해 확인한 결과가 아닙니다.

- 사용자가 선택한 그 날짜의 주문만 집계합니다. 누적 합계가 아닙니다.
- paid만 포함하고 cancelled는 제외합니다.
- 같은 order_id에 같은 내용이 반복되면 한 건으로 취급합니다. 내용이 다른 중복은 임의 선택하지 않고 보류합니다.
- 금액 누락·잘못된 형식은 합계에서 제외하되 오류 건수와 원행을 드러냅니다. 조용히 0으로 바꾸지 않습니다.
- 금액은 소수 둘째 자리 단위로 정확히 취급해야 합니다. 날짜·상태·필수 열 검증도 고려합니다.
- 결과는 선택 날짜, 합계, 반영 건수와 제외·오류 이유를 설명할 수 있어야 합니다.

## 기대 사례

- 2026-11-10: O001과 O002 한 건씩이므로 합계 **20.00**. 중복 복사본과 취소 건은 합계에서 제외합니다.
- 2026-11-11: O004의 **3.10**, O005 금액 누락을 별도로 드러냅니다. 전날 거래가 섞이지 않습니다.
- 없는 날짜: 합계와 건수를 어떻게 표시할지 설명하고 날짜 형식 오류와 구분합니다.
- 수정 이후: 이전에 맞던 날짜도 유지되는지 허용 범위의 회귀 근거 또는 NOT_RUN을 남깁니다.

## 사고 과정

기대값·실제 출력·원인·수정 범위를 분리합니다. 중복, 취소, 날짜 필터, 잘못된 금액을 각각 독립 원인으로 확인합니다. float 대신 무엇을 사용할지와 출력에서 20.00을 어떻게 다룰지도 선택 이유가 필요합니다.

완성 코드는 제공하지 않습니다. 이 폴더를 자동 테스트로 실행하거나 실제 시험의 정답으로 쓰는 것이 목적이 아닙니다.
