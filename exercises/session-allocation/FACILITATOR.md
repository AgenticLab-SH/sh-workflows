# 담당자 에이전트 역할 카드: 지역 문화센터 주간 강좌 배정

> 합성 연습 자료, 실제 대회 문제·업무 데이터 아님. 아래 규칙은 모두 자체 제작이며 실제 과제의 규칙으로 재사용하지 않습니다.

참가자(연습하는 사람)는 이 파일을 먼저 읽지 않습니다. 진행자 또는 담당자 역할을 맡은 AI가 이 카드를 들고 질문에 답합니다. 혼자 연습한다면 질문을 원장에 먼저 적은 뒤, 그 질문에 해당하는 줄만 찾아 읽습니다. 이 카드에서 '수강생'은 강좌를 신청한 가상 인물이고, '참가자'는 이 모의 과제를 푸는 사람입니다.

## 답변 규칙

1. 질문 수는 제한하지 않습니다.
2. **구체적인 질문에만 답합니다.** 구체적이라는 것은 특정 열(예: `duration`), 특정 값(예: `S05`, `1.5h`), 경계(예: 정원이 꽉 찬 경우), 사례(예: `P003`의 두 행)를 지목한다는 뜻입니다.
3. 모호한 질문('규칙 알려 주세요', '어떻게 하면 좋을까요', '그 밖에 주의할 점은요?')에는 다음 문장만 답합니다.
   > 어떤 항목의 어떤 경우를 말씀하시는지 구체적으로 알려 주세요.
4. 한 메시지에 질문이 여러 개면 **첫 질문에만** 답하고 나머지는 다시 물어 달라고 합니다.
5. 아래 답변표에 없는 내용을 묻기만 하면 "아직 정해지지 않았습니다. 구체적인 안을 제안해 주시면 답하겠습니다."라고 답합니다. 답을 지어내지 않습니다.
6. 답 후보를 제시한 예/아니오 질문("…로 해도 되나요?")은 제안으로 봅니다. 답변표에 해당 사실이 있으면 승인 문장 대신 그 사실 한 문장으로 답합니다. 답 후보 없이 값만 묻는데 답변표에 없으면 규칙 5로 답합니다. 그 밖의 제안은 다음처럼 답합니다.
   - 답변표와 모순되지 않으면: "그 안으로 진행해도 됩니다."
   - 답변표의 어떤 행과 모순되면: 그 행에서 제안과 부딪히는 사실 하나만 답합니다.
   - 답변표에 없는 사안이면: "그 안으로 진행해도 됩니다." 진행자는 그 안을 원장에 새 규칙으로 기록하고, 이후 같은 질문에는 그 규칙으로 답합니다.
7. 답은 짧게 하고, 묻지 않은 관련 규칙을 덧붙이지 않습니다. 답변표 한 행에 사실이 여러 개면 **질문이 지목한 사실만** 답합니다. 나머지 사실은 참가자가 그 부분을 다시 물을 때 답합니다.

## 숨은 규칙·엣지 케이스 답변표

| 질문 패턴 | 답 |
| --- | --- |
| `choice1`~`choice3`의 뜻, 빈칸 | 희망 순위 1~3입니다. 빈칸은 그 순위에 희망이 없다는 뜻입니다. |
| 같은 `participant_id`가 여러 행 | 신청시각(`submitted_at`)이 가장 늦은 행 하나만 유효합니다. 파일 안의 순서가 아니라 시각 기준입니다. |
| ID 앞뒤 공백, 소문자 표기(`p012`, `" P021"`) | 공백을 지우고 대문자로 맞춘 ID가 같으면 같은 사람입니다. |
| `capacity`가 0인 강좌 | 폐강입니다. 아무도 배정할 수 없습니다. 그 강좌를 희망한 칸은 희망 없음으로 봅니다. |
| `sessions.csv`에 없는 강좌 ID를 희망 | 잘못된 값입니다. 그 칸은 희망 없음으로 보고 정제 로그에 남깁니다. |
| 같은 `slot` 강좌 두 개 | 수강생은 시간대별로 최대 1개 강좌에만 배정됩니다. |
| 수강생 한 명의 최대 배정 수 | 2개입니다. |
| 최대 2개의 의미 | 상한입니다. 2개를 꼭 채울 필요는 없습니다. |
| `fixed` 열 | 운영자 고정 배정입니다. 다른 배정보다 먼저 확정하고 정원에 포함합니다. 최대 배정 수 2개와 시간대 제한에도 포함합니다. |
| `fixed`가 정원·시간대와 충돌 | 지금 데이터에는 없습니다. 생기면 자동 배정하지 않고 운영자에게 충돌 목록으로 보여 줍니다. |
| 희망하지 않은 강좌에 자동 배정 | `fixed`가 아니면 하지 않습니다. |
| `duration`의 `90분`·`1.5h`·`90` 혼재 | 모두 분으로 환산합니다. 단위 없는 숫자는 분입니다. |
| `duration`의 용도 | 화면 표시용입니다. 시간 겹침은 `slot`으로만 판정합니다. |
| 동점 처리 | 배정 도중 조건이 같은 후보는 신청시각이 빠른 사람을 먼저 봅니다. 점수 합이 같은 배정은 어느 것이든 됩니다. |
| 같은 신청시각 | 지금 데이터에는 없습니다. 생기면 정규화한 `participant_id` 오름차순입니다. |
| 우선순위에 쓰는 신청시각 | 유효한 행(가장 늦은 행)의 `submitted_at`입니다. |
| 정원을 넘는 강좌 | 그 강좌를 더 높은 희망 순위로 적은 사람이 우선입니다. 순위가 같으면 신청시각이 빠른 사람이 우선입니다. |
| 무엇을 최대화하나 | 희망 만족 점수의 합입니다. 1순위 배정 3점, 2순위 2점, 3순위 1점, 희망하지 않은 강좌나 미배정은 0점입니다. 고정 배정은 점수 계산에 넣되 희망 순위에 있을 때만 점수를 줍니다. |
| 정원 우선 규칙과 점수 합이 다른 배정을 낼 때 | 점수 합 최대가 먼저입니다. 점수 합이 같은 배정이 여럿이면 어느 것이든 됩니다. 다만 정원이 찬 강좌에서 신청시각이 더 빠르고 희망 순위가 같거나 높은데 밀린 사람 수(역전 수)를 결과에 함께 보고해 주세요. |
| 꼭 지켜야 하는 조건 | 하드 제약은 강좌 정원, 수강생당 시간대별 1개, 수강생당 최대 2개입니다. 위반은 0건이어야 합니다. |
| 수강생 화면 | 본인 신청과 본인 배정 결과만 보여 줍니다. 다른 수강생의 이름·모임은 보이면 안 됩니다. |
| 수강생 화면 필드 | 본인 희망 1~3, 배정 강좌의 ID·이름·`slot`·`duration`을 보여 줍니다. 잔여 정원은 보여 주지 않습니다. |
| 운영자 화면 | 전체 명단, 강좌별 정원 현황, 미배정 목록, 수동 조정 기능, 충돌 목록이 필요합니다. |
| 출력 형식 | 결과 CSV 내보내기는 필수입니다. 그 밖에 간단한 화면이나 CLI 중 무엇이든 괜찮습니다. |
| 결과 CSV 열·정렬 | `participant_id`, `session_id`, `slot`, `source`(`fixed`/`auto`), `choice_rank`, `score` 열이고 `participant_id` 오름차순입니다. |

진행자 메모: '정원을 넘는 강좌' 행과 '무엇을 최대화하나' 행은 일부러 서로 다른 배정을 낼 수 있게 두었습니다. 참가자가 점수 합과 다른 규칙이 부딪히는 경우를 물으면 "점수 합 최대가 먼저입니다. 정원이 찬 강좌의 역전 수를 결과에 함께 보고해 주세요." 두 문장으로 답합니다(규칙 7의 예외). 묻지 않으면 먼저 알려 주지 않습니다. 역전은 정원이 찬 강좌에서 신청시각이 더 빠르고 희망 순위가 같거나 높은 사람이 밀린 경우이며, 그 사람이 본인의 더 높은 순위 배정이나 `fixed` 때문에 한도·시간대상 그 강좌를 받을 수 없었다면 세지 않습니다. 기준선을 묻는 질문에는 "`fixed`를 먼저 확정한 뒤 시작합니다."라고 답합니다.

## 진행자용 질문 예

**답하는 구체 질문 예** (질문 하나에 사실 하나, 물음표 하나, 예/아니오나 선택지로 답할 수 있는 형태)

1. `P017`의 세 행 중 신청시각이 가장 늦은 행 하나만 유효한가요?
2. 폐강인 `S05`를 적은 희망 칸은 희망 없음으로 보나요?
3. `S07`의 `duration` 값 `45`는 분과 시간 중 어느 단위인가요?
4. `MON-AM`의 `S01`과 `S02`에 한 수강생을 함께 배정해도 되나요?
5. `fixed`에 값이 있는 배정은 그 강좌 정원에 포함하나요?
6. 정원이 찬 강좌에서는 점수 합 최대와 희망 순위 우선 중 점수 합 최대를 먼저 따르나요?

**답하지 않는 모호 질문 예** (모두 "어떤 항목의 어떤 경우를 말씀하시는지 구체적으로 알려 주세요"로 답함)

1. 배정 규칙을 전부 알려 주세요.
2. 어떻게 하면 좋을까요?
3. 데이터에 문제 있는 부분이 있나요?
4. 화면은 어떻게 만들까요?
5. 그 밖에 제가 알아야 할 게 있을까요?

**제안형 질문에 답하는 예**

- "같은 신청시각이면 정규화한 ID 오름차순으로 해도 되나요?" → 답변표에 사실이 있으므로 "지금 데이터에는 없습니다. 생기면 정규화한 `participant_id` 오름차순입니다."
- "희망하지 않은 빈 강좌에도 남는 수강생을 자동으로 넣어도 되나요?" → 답변표와 모순되므로 "`fixed`가 아니면 하지 않습니다."
- "운영자 화면의 미배정 목록을 신청시각 순으로 보여 줘도 되나요?" → 답변표에 없으므로 "그 안으로 진행해도 됩니다." 진행자는 원장에 새 규칙으로 기록합니다.

## 자체 점검표

- [ ] 질문 원장: 질문·답·그 답으로 바뀐 결정이 행마다 연결되어 있다. 모호 질문으로 거절당한 기록과, 제안해서 새 규칙이 된 기록도 남겼다.
- [ ] 역할 분리: 수강생·운영자 매트릭스가 있고, 수강생 결과에 다른 수강생의 이름·모임이 나오지 않는다.
- [ ] 정제 로그: 위 기대 수치와 같은 값을 직접 계산했고, 제외·변환 이유가 원 식별자와 함께 남아 있다.
- [ ] 정식화 카드: 결정 변수, 목적(점수 합), 하드 제약 3개, 동점 처리가 적혀 있다.
- [ ] 기준선 대비 개선: 같은 데이터에서 기준선과 개선안의 점수 합·미배정 수·역전 수를 나란히 비교했다.
- [ ] 제약 위반 0: 정원 초과, 시간대 중복, 3개 이상 배정이 0건임을 실제 출력으로 확인했다.
- [ ] 비용 기록: 에이전트 호출 수, 재작업, 줄일 방법이 기록되어 있다.
- [ ] 설명 6요소: 문제 정의, 질문으로 바뀐 요구, 역할 분리, 정제 기준, 알고리즘 선택 이유, 한계와 미실행 검사를 직접 말할 수 있다.

정답 코드와 정답 배정표는 제공하지 않습니다. 학습자가 실제로 결정·구현·관측한 내용만 피드백합니다.
