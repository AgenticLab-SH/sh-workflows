# 정보 습득부터 내 설명까지 연결하는 사전 연습

실제 과제나 기출을 풀어 둔 자료가 아니다. 기존 Skill과 도구를 연결하는 **작은 합성 예시**다. 최신 공식 규칙이 우선이며, 실제 AI 금지 단계에서는 이 문서로 답변·메모를 만들거나 AI를 호출하지 않는다. 개인 일정·실제 과제·복기 원문을 공개 키트에 적지 않는다.

## 혼자 시작하는 방법

처음에는 아래 블록 하나만 사전 학습 환경의 AI에 전달한다. 실제 평가 자료를 외부 AI에 붙이지 않는다.

```text
지금은 실제 평가가 아닌 합성 사전 연습이다.
이 키트의 hackathon-task-driver를 시작점으로 삼아라.
먼저 examples/method_trace.py의 합성 입력과 이 문서의 짧은 의뢰만 보여 줘라.
내가 결과를 바꿀 공백과 구체 질문을 먼저 적을 때까지 해설·답안을 주지 마라.
그 뒤 내가 고른 질문에 해당하는 합성 설정만 하나씩 확인하자.
기준선과 후보의 전제·비용·보장 범위를 내가 비교한 뒤 기존 도구를 실행하자.
실행을 허용하지 않는 정책이면 NOT_RUN으로 멈추고 실행을 꾸미지 마라.
완료한 요구 하나의 질문ID→결정→함수→관측→한계를 추적하자.
상세 설명은 내가 먼저 답하고 가장 약한 연결에 대해서만 한 질문씩 해라.
실제 AI 금지 단계가 시작되면 지원을 중단해라.
```

AI 없이 연습하려면 짧은 의뢰→질문 작성→원장의 해당 행만 확인→방법 비교→허용 실행→아래 자가 질문 순으로 한다. 먼저 자신의 예측을 종이에 적고 출력과 비교한다. 기록 위치는 공개 소스 밖의 개인 연습 폴더다. 코드를 읽기 어려우면 함수 이름 암기 대신 입력 한 건의 이동과 실패 조건부터 설명한다.

## 1. 의뢰와 정보 공백

자체 의뢰: “동네 행사 준비 항목을 예산 안에서 골라 주세요. 메모에는 비용 대비 효율 우선과 전체 효과 최대라는 표현이 함께 있습니다.”

기존 `opt_kit.py` 예산 데모의 숫자를 재사용한다. 효과 점수도 자체 합성 값이며 실제 효용·매출·공식 평가점수가 아니다.

| 항목 | 비용(같은 단위라는 가정) | 효과 점수 |
| --- | --- | --- |
| A | 10 | 60 |
| B | 20 | 100 |
| C | 30 | 120 |

의뢰만으로 확정할 수 없는 것: 총예산, 쪼개기, 각 항목의 선택 횟수, 효과의 합산 가능성, 필수 항목, 동점, 두 목적의 우선순위. 이 숫자나 기술 논문으로 업무 규칙을 추정하지 않는다.

[합성 질문 원장](../examples/method_trace_questions.csv)은 **작성자가 정한 연습 가정**이다. 모든 행은 `assumed`, `ask_count=0`이다. 담당자·사용자에게 질문을 보내거나 답을 받은 기록이 아니다. 실제 과제에서는 허용된 담당자의 실제 답을 받기 전 `answered`로 바꾸지 않는다. 쪼개기 금지(Q03), 반복 선택 금지(Q09), 항목 간 선택 독립성(Q10)은 서로 다른 가정이므로 따로 기록한다.

- 업무 규칙·충돌: Q01~Q05·Q07~Q10처럼 담당자에게 사실 하나씩 묻는다.
- 실제 입력: 필드·단위·결측·중복은 파일에서 확인하고 애매한 뜻은 Q06처럼 묻는다. 이 예시는 메모리 안의 3개 항목으로 한정해 파일 정제는 구현하지 않았다.
- 기술: 정수 예산에서 가능한 선택을 비교하는 방법과 크기 한계만 1차 자료로 확인한다.
- 환경·제출: 공식 안내에서 확인한다. 최신 허용 여부가 없으면 옛 안내나 이 예시를 근거로 반입·실행을 확정하지 않는다.

## 2. 정식화와 후보 비교

이번 **합성 가정**: 예산 50 포함, 항목마다 0/1회, 비용은 같은 단위의 0 이상 정수, 효과는 단순 합, 필수 항목·상호의존성 없음, 같은 최대 점수면 어느 조합도 허용한다. 실제 필수 항목이 생기면 모델을 먼저 바꿔야 한다.

`x_i=1`은 항목 i를 고른다는 뜻이고 `0`은 고르지 않는다는 뜻이다. 효과 합 `sum(value_i*x_i)`를 최대로 하되 비용 합 `sum(cost_i*x_i)<=50`을 지킨다. “가장 효율 좋은 것부터”는 이 목적의 정답을 보장하지 않는다.

| 후보 | 맞는 조건·보장 | 비용·한계 | 이번 판단 |
| --- | --- | --- | --- |
| 비율 탐욕 `greedy_knapsack` | 효율 순서로 넣는 쉬운 기준선. 용량은 지키지만 0/1 최적 보장 없음 | 정렬 O(n log n), 작은 구현 | 기준선으로 실행 |
| 정수 예산 DP `knapsack_01` | 위 단일 예산·독립 선택 모델의 정확해. S1의 정수 용량 가정과 일치 | 시간 O(nC). 기존 구현은 점수 배열 O(C) 외에 선택 복원용 O(nC) 메모리도 씀 | n=3·C=50에서 채택 |
| 모든 부분집합 검사 | 모든 조합을 보므로 이 모델의 정확해 | 구현은 O(n*2^n). 연습 oracle은 n<=12로 제한 | 독립 검산에만 사용 |
| OR-Tools 배낭 solver | 공식 S2의 정수 입력·분기 한정 후보 | 별도 의존성·버전·모델 적합성 확인 필요. 이번 속도는 NOT_RUN | 기존 표준 라이브러리 도구로 충분해 미채택·미설치 |

S1은 논문 대신 이번 기초 원리를 확인하기에 충분한 공식 강의 원문이다. 새 논문이나 외부 코드는 채택하지 않았다. 출처 제목·절·확인일·라이선스는 [영구 출처 기록](RESEARCH_METHODS.md#합성-방법-선택-원문-확인)에 있다. 실제 과제가 생기면 그 입력·규모·제약으로 후보 표를 다시 만든다.

DP는 같은 작은 문제의 결과를 저장해 다시 쓰는 방법이다. “지금까지 본 항목과 남은 예산”에 대해 이번 항목을 빼는 경우와 넣는 경우를 비교한다. 기존 구현이 예산을 큰 쪽부터 훑는 이유는 같은 항목을 한 회차에 반복 선택하지 않기 위해서다. 용량 C의 **숫자 자체**가 커지면 작업량이 커지는 의사다항 시간이며, 비용 단위를 임의 반올림해 줄이면 경계와 정답도 달라질 수 있다. 기존 5,000,000 셀 guard는 메모리·실행시간의 일반 보증이 아니다. 점수는 내부 float와 EPS를 쓰므로 아주 큰 수·극히 작은 점수 차이는 별도 검토가 필요하다.

## 3. 구현과 실행 근거

새 알고리즘을 복제하지 않고 [연결 예제](../examples/method_trace.py)가 기존 [최적화 도구](../tools/opt_kit.py)의 두 함수를 호출한다. 예제의 `enumerate_best`는 DP와 다른 방식으로 부분집합을 전부 살펴 검산한다. 네트워크·외부 입력·파일 출력은 없다.

준비 환경에서 Python이 이미 있고 검사가 허용될 때 키트 루트에서 실행한다. Windows는 `python`, Linux 제공 환경은 공식 명령이 `python3`이면 그것을 쓴다. 설치·업데이트는 필요하지 않다.

```text
python -B examples/method_trace.py
python -B tools/question_ledger.py lint examples/method_trace_questions.csv
python -B -m unittest discover -s tests -p test_method_trace.py -v
```

실행 전 예측: 탐욕은 A+B로 30을 쓰고 160점, DP는 B+C로 50을 쓰고 220점이다. 절대 개선은 60점이다. 예산이 남는다고 더 좋은 선택인 것은 아니다. 예산 30으로 바꾸면 A+B의 160점이 최대다. 이는 실행 기록을 읽기 전에는 계산상 기대값이다.

최신 **실제 로컬 실행**과 NOT_RUN은 [연결 검증 기록](METHOD_TRACE_VALIDATION.md)을 본다. 개별 출력의 `elapsed_ms`는 한 번 측정한 값이며 속도 우월성·실제 평가환경 성능을 보증하지 않는다. 작은 정확해 대조는 바뀐 제약의 모델링 정확성이나 큰 입력 성능까지 증명하지 않는다.

선택형 추가 연습: [Hypothesis 반례 탐색·축소](OSS_ADOPTION.md)는 같은 entrypoint의 --property-checks 옵션으로 실행한다. 설치·규칙 허용을 따로 확인하며 기존 기본 모드에는 의존성이 없다.

## 4. 요구→설명 추적

기존 [요구 연결표](../templates/REQUIREMENT_TRACEABILITY.md)와 [출처 양식](../templates/ATTRIBUTION.md)을 재사용한다. 새 원장을 중복 생성하지 말고 같은 ID로 잇는다.

| 질문/결정 | 구현 위치 | 사례·관측 연결 | 본인이 설명할 것 |
| --- | --- | --- | --- |
| Q01·Q03·Q04·Q05·Q09·Q10 → D01: 예산 포함·0/1·가산 효과 | `knapsack_01`; 예제 `compare_case` | `ratio_counterexample`: 비용 50, 부분집합 최댓값 대조 | 왜 절반 선택이나 반복 선택을 하지 않는가 |
| Q02 → D02: 총효과가 목적, 효율은 기준선 | `greedy_knapsack`와 `knapsack_01` | 같은 사례의 점수 차이, 위반 수 별도 출력 | A부터 골랐을 때 놓친 조합은 무엇인가 |
| Q06 → D03: 정수 단위 유지 | `knapsack_01` 입력 검사 | `fractional_cost`·`negative_cost` 거절 | 1.5를 임의로 1로 바꾸면 왜 안 되는가 |
| Q07 → D04: 동점 조합 어느 것이든 허용 | 기존 DP의 엄격한 개선 비교 | `tied_optimum`: 점수와 제약만 검사 | 동일 점수면 특정 ID·공정성이 보장되는가 |
| Q08 → D05: 관측 가능한 CLI 출력 | 예제 `run` | ID·사용 예산·목적값·시간·NOT_RUN 출력 | 출력이 실제 제출이나 화면 검증을 뜻하는가 |

실제 질문 답변이 뒤집히면 해당 D번호의 모델·함수·검사·설명만 함께 고친다. 예를 들어 A가 필수라면 현재의 무제약 B+C는 쓸 수 없다. 이때 알고리즘을 그대로 두고 설명만 바꾸면 안 된다. 필수 선택 선처리·잔여 용량·점수 합산과 충돌 검사를 추가해야 하며 이 예제에는 구현하지 않았다. 두 예산, 묶음, 선후행 의존성도 별도 모델이 필요하다.

## 5. 내 힘으로 설명하고 반례에 답하기

먼저 교육 설명을 읽고 입력 하나를 따라간다. 그다음 해설을 닫고 아래에서 하나를 골라 본인이 먼저 답한다. 정답 문장을 외우는 방식으로 채우지 않는다.

1. A의 효율이 가장 높은데도 A를 빼는 결과를 왜 선택했는가?
2. 예산을 30으로 바꾸면 무엇을 예상하고 어떤 실제 출력으로 확인하겠는가?
3. 비용 1.5가 들어오면 현재 함수는 어떻게 동작하며 누구에게 무엇을 확인해야 하는가?
4. A 필수나 A·C 동시 선택 금지가 생기면 어느 가정과 코드·검사가 달라져야 하는가?
5. “작은 테스트 통과”와 “큰 입력에서도 빠르고 내 모델이 업무에 맞다”는 왜 다른가?
6. 현재 프로그램이 DB에 결과를 저장했다는 질문을 받으면 어떤 사실로 전제를 바로잡겠는가?

답을 쓴 뒤에만 [깊이별 연습](../.agents/skills/short-answer-defense/references/follow-up-practice.md)으로 사실 일치·원인·구체 근거·한계를 대조한다. 답하지 못한 연결 하나를 학습 대상으로 남기고 다른 작은 입력으로 다시 예상한다. 사용자 답변·직접 설명·이해 확인은 **미실시**다. 이 자료를 만든 것과 본인의 학습 완료는 다르다.

다음 독립 연습은 [모의 D](../exercises/session-allocation/BRIEF.md) 또는 [모의 E](../exercises/donation-packing/BRIEF.md)의 의뢰부터 시작한다. 이 예제를 실제 과제의 알고리즘 정답으로 사용하지 않는다.
