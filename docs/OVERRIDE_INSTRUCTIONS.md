# 오버라이드 지침 운영서

공식 규칙·제공 환경·호스트 정책이 이 문서보다 우선한다. 오버라이드는 Codex의 **작업 방식 기본값**을 정하는 층이며, 어떤 규칙도 해제하거나 우회하지 않는다. 문제 정의·업무 결정·최종 설명은 참가자가 맡는다.

## 경로 결정 순서 (먼저 볼 것)

과제 루트에서 위에서부터 차례로 확인하고, 처음 맞는 줄의 경로를 쓴다.

| 순서 | 과제 루트 상태 | 경로 | 하는 일 |
|---|---|---|---|
| (a) | `AGENTS.override.md`가 이미 있음 | **경로 B** | 제공물로 본다. 만들지도 고치지도 않는다. 첫 메시지 블록만 쓴다. |
| (b) | 제공 원본 `AGENTS.md`가 없음 | **경로 A** | 루트에 `AGENTS.override.md`를 둔다. 가려지는 파일이 없다. |
| (c) | 제공 원본 `AGENTS.md`가 있음 | **경로 A2** (기본) | override 맨 위에 원본 전문을 한 글자도 바꾸지 않고 붙이고, 구분선 아래에 참가자 작업 방식을 덧붙인다. 원본 파일은 지우거나 고치지 않는다. 원본 규칙이 시작 지침에서 빠지지 않는다. |
| (c') | (c)인데 원본 복사가 공식 규칙상 애매하거나, 원본이 길어 합계가 32KiB에 가까움 | **경로 B** | 파일을 만들지 않고 첫 메시지 블록을 쓴다. |
| (d) | 산출물 경로가 하위 작업 폴더여도 될 때만 | 하위 폴더 대안 | `work/` 같은 하위 폴더에 override를 두고 그 폴더에서 Codex를 시작한다. 루트 원본이 먼저, override가 뒤에 들어간다. |

- **만드는 시점**: 첫 작업 세션을 시작하기 전에 만든다. 지침은 세션 시작 때 한 번만 구성된다.
- **실행 주체**: Codex는 override 초안만 제안한다. 파일을 만들지, 새 세션을 열지는 참가자가 결정한다. Codex는 지시 없이 지침 파일을 만들거나 세션을 바꾸지 않는다.
- **빈 파일**: 빈 override를 두지 않는다. 같은 폴더의 원본까지 안 읽힐 수 있다(동작 미확정, 아래 표 참고).

## 무엇이고 왜 효과적인가

- `AGENTS.override.md`는 Codex가 시작할 때 자동으로 읽는 지침 파일이다. 같은 폴더에서는 `AGENTS.md`보다 먼저 선택된다.
- 매 요청마다 "질문은 이렇게, 검사는 이것만, 출력은 짧게"를 반복하지 않아도 첫 요청부터 같은 방식이 적용된다.
- 시간이 짧은 과제에서 역할 구분, 담당자 질문 방식, 비용 절약, NOT_RUN 기록이 처음부터 고정되므로 중간에 흐트러지지 않는다.

## 사용 전제

- 공식 규칙이 참가자가 작성한 지침 파일이나 프롬프트를 허용할 때만 쓴다.
- 허용 여부가 분명하지 않으면 Helper 또는 공식 문의 창구에 먼저 묻는다. 예: "참가자가 작업 폴더에 직접 쓴 AGENTS.override.md 지침 파일을 두어도 됩니까? (예/아니오)"
- 경로 A2는 원본 내용을 override 파일에 복사한다. 이것이 허용되는지 애매하면 따로 묻는다. 예: "제공된 AGENTS.md 내용을 참가자 지침 파일 맨 위에 그대로 옮겨 적어도 됩니까? (예/아니오)" 답이 없으면 경로 B를 쓴다.
- 템플릿에는 일반 작업 방식만 있다. 실제 과제 내용은 시험 환경 안에서 참가자가 직접 채운다.

## Codex가 지침을 읽는 방식 (공식 문서 기준)

| 범위 | 규칙 |
|---|---|
| 전역 | Codex 홈(`~/.codex` 또는 `CODEX_HOME`)에서 `AGENTS.override.md`가 있으면 그것을, 없으면 `AGENTS.md`를 읽는다. 비어 있지 않은 첫 파일 하나만. |
| 프로젝트 | 프로젝트 루트(보통 Git 루트)부터 현재 작업 폴더(cwd)까지 내려가며 폴더마다 `AGENTS.override.md` → `AGENTS.md` → `project_doc_fallback_filenames` 순으로 확인하고 **폴더당 1개만** 넣는다. 루트를 못 찾으면 cwd만 본다. |
| 순서 | 루트→cwd 순으로 이어 붙인다. cwd에 가까운 파일이 뒤에 와서 우선한다. |
| 빈 파일 | 공식 문서는 빈 파일을 건너뛴다고만 적는다. 같은 폴더에서 빈 override 다음 `AGENTS.md`로 넘어가는지는 밝히지 않는다. **빈 override를 두지 않는다**(원본까지 안 읽힐 수 있음, 동작 미확정). |
| 상한 | 합계가 `project_doc_max_bytes`(기본 32KiB)에 닿으면 더 넣지 않는다. |
| 반영 시점 | 실행 또는 세션 시작 때 한 번 구성한다. 파일을 만든 뒤에는 Codex를 새로 시작하거나 새 세션을 열어야 한다. |

핵심 결과: **같은 폴더에 override가 있으면 그 폴더의 `AGENTS.md`는 시작 지침에서 빠진다(가려짐).** 경로 A2는 원본 전문을 override 안에 넣어 이 손실을 막는다.

## 경로 A / A2: AGENTS.override.md 파일 두기

1. 과제 루트에서 `AGENTS.override.md`와 `AGENTS.md`가 있는지 확인한다. override가 이미 있으면 여기서 멈추고 경로 B로 간다. 원본은 어느 경로에서도 지우거나 고치지 않는다.
2. Codex에게 초안을 요청한다: "templates/AGENTS.override.template.md를 바탕으로 AGENTS.override.md 초안을 보여 줘. 파일은 아직 만들지 마." 파일 생성 여부는 참가자가 정한다.
3. 경로 A(원본 없음): 템플릿 첫 줄의 원본 자리와 구분선을 지운다.
4. 경로 A2(원본 있음): 첫 줄 `[원본 AGENTS.md가 있으면 이 줄 아래에 원본 전문을 그대로 붙인다]` 아래에 원본 `AGENTS.md` 전문을 그대로 붙인다. 요약·번역·줄 정리를 하지 않는다. `--- 아래는 참가자 작업 방식 ---` 구분선과 그 아래 0번 문장("같은 폴더에 AGENTS.md(제공 원본)가 있으면 먼저 읽고…")은 지우지 않는다.
5. `{...}` 자리만 채운다. 참가자 부분은 2.5KB 안팎으로 짧게 둔다. 원본과 합쳐 32KiB에 가까우면(예: 28KiB 이상) 경로 B로 바꾼다.
6. 새 세션을 연다. 첫 작업 세션 전이면 그대로 시작한다. 이미 대화가 진행된 뒤 만들었다면, 새 세션을 열기 전에 현재 세션에 "지금까지의 결정·질문 원장·남은 일을 10줄 이내로 요약해 줘"라고 요청하고, 그 요약을 새 세션 첫 메시지에 붙인다.
7. 반영 확인: "지금 적용 중인 지침 파일 출처와 핵심 규칙 3줄을 요약해라." 원본 규칙과 참가자 작업 방식이 둘 다 나오면 정상이다.
8. 시험 중 원본 `AGENTS.md`가 바뀌면 override의 원본 부분도 다시 그대로 붙이고 새 세션을 연다.

선택 점검(로컬 Python이 허용될 때): 파일 선택·가려짐·원본 포함 여부·크기를 메타데이터만으로 확인한다. 내용은 출력하지 않는다.

```text
python3 .hackathon-kit/tools/instruction_chain.py --root .
```

`.hackathon-kit`은 키트를 둔 위치에 맞게 바꾼다. 하위 폴더에서 시작한다면 `--cwd work`처럼 덧붙인다.

- `original_embedded: true`: override가 원본 전문으로 **시작한다**. 비교 전에 BOM을 지우고, 줄바꿈 CRLF/CR을 LF로 맞추고, 줄 끝 공백과 앞뒤 빈 줄을 지운다(원본 첫 줄의 들여쓰기는 그대로 비교). 원본 앞에는 빈 줄, 템플릿 안내 줄 `[원본 AGENTS.md가 있으면 이 줄 아래에 원본 전문을 그대로 붙인다]`, HTML 주석(`<!-- ... -->`)만 올 수 있다. 원본 마지막 줄까지 줄 단위로 같아야 한다. `notes`에 `embeds original`이 나온다.
- `original_embedded: false`: 원본이 override 맨 위에 그대로 있지 않다. 원본을 아래쪽에 붙였거나, 한 글자·들여쓰기라도 바뀌었거나, 원본 앞에 다른 내용이 있는 경우다. `warnings`에 `hides AGENTS.md`가 나온다. 원본을 맨 위에 그대로 붙이거나 경로 B를 쓴다.
- `original_embedded: null`: 비교하지 않았다. 같은 폴더에 override가 없거나, 파일이 너무 커서 비교를 건너뛰었거나(`warnings`에 `too large to compare`), 원본 `AGENTS.md`가 비어 있다(`notes`에 `original AGENTS.md is empty`, 붙일 내용이 없으므로 경고는 없다).
- `warnings`에 `behavior unconfirmed`가 있으면 빈 지침 파일이 있다는 뜻이다. 내용을 채우거나 파일을 쓰지 않는다.

이 점검기는 문서 규칙 기준의 근사이며 전역 Codex 홈은 점검하지 않는다.

## 경로 B: 세션 첫 메시지에 붙이기

(a)·(c') 경우, 또는 파일을 만들었는데 반영되지 않으면 `templates/PROMPT_OVERRIDE_BLOCK.md`의 블록을 세션 첫 메시지 맨 위에 붙이고 첫 요청을 이어 쓴다. 이 방법은 어떤 지침 파일도 가리지 않는다. 이전 세션에서 넘어왔다면 결정·질문 원장·남은 일 요약을 블록 아래에 붙인다. 블록 마지막 줄의 3줄 요약 답으로 반영을 확인한다.

## 경로 C: 그래도 무시될 때

- 위임 요청마다 핵심 3줄을 앞에 다시 쓴다. 예: "원본 지침 우선 / 모호하면 질문 멘트 작성 / 못 한 검사는 NOT_RUN".
- 대화가 길어져 지침이 흐려지면 지금까지의 결정·질문 원장·남은 일을 요약하게 한 뒤 새 세션을 열고 블록과 요약을 함께 붙인다.

## 하지 말 것

- 이미 있는 `AGENTS.override.md`를 덮어쓰거나 고치기.
- 전역 `~/.codex`(또는 `CODEX_HOME`)의 지침·설정 수정.
- 제공 환경의 설정·모델·승인·샌드박스 변경.
- 제공 원본 지침이나 과제 파일 삭제·수정. A2에서도 원본 파일은 그대로 둔다.
- 원본을 요약·발췌해 override에 넣기. 붙일 때는 전문을 그대로 붙인다.
- 상위 호스트 정책이나 공식 규칙을 "무시하라"는 문구. 오버라이드는 작업 방식 층이며 규칙 우회 수단이 아니다.
- 외부 AI 전송, Git Push, 캡처·GUI 자동화, Codex 업데이트, 감독 우회(금지).

## 제출 전

- override 파일이 제출 후보에 포함되는지 공식 미리보기에서 확인한다.
- 포함할지는 참가자가 공식 안내에 따라 결정한다. 확인 없이 임의로 지우지 않는다.
- 자세한 확인은 `reference-submission-review` Skill과 `templates/PRE_SUBMISSION.md`를 쓴다.

## 문제 해결

| 증상 | 확인할 것 | 조치 |
|---|---|---|
| 지침이 반영되지 않음 | 파일명 철자(`AGENTS.override.md`), 위치가 루트~cwd 경로 위인지, 파일 생성 후 새 세션을 열었는지 | 새 세션. 안 되면 경로 B |
| 루트에 override가 이미 있음 | 제공물일 수 있음 | 만들지도 고치지도 않는다. 경로 B |
| 원본 규칙이 사라짐 | 같은 폴더 override가 원본을 가림. 점검기의 `original_embedded` | 원본 전문을 override 맨 위에 그대로 붙이거나 경로 B |
| `original_embedded: false`인데 붙였음 | 원본을 맨 위가 아닌 곳에 붙였는지, 원본 앞에 다른 글이 있는지, 원본 일부(들여쓰기 포함)를 고쳤거나 빠뜨렸는지 | 원본 파일에서 전문을 다시 복사해 안내 줄 바로 아래에 붙인다 |
| 내용이 잘림·뒤쪽 무시 | 합계가 32KiB 상한에 닿음 | 참가자 부분을 줄이고, 그래도 크면 경로 B |
| 세션 중간에 파일을 만듦 | 지침은 시작 때 한 번만 구성됨 | 결정·질문 원장·남은 일 요약을 받아 새 세션 첫 메시지에 붙인다 |
| 빈 파일로 둠 | 빈 override 다음 파일로 넘어가는지 공식 문서에 없음. 원본까지 안 읽힐 수 있음(동작 미확정) | 빈 override를 두지 않는다. 내용을 채우거나 파일을 쓰지 않음 |
| 하위 폴더에서 시작했더니 다른 지침이 섞임 | 루트~cwd 사이 폴더의 지침도 모두 들어감 | `instruction_chain.py`로 load_order 확인 |
| 규칙끼리 충돌 | 원본·공식 규칙이 우선 | 충돌 사실을 참가자에게 알리고 Helper에 문의 |
