# 제출 단계와 장애 대응

Notion의 시험 지도·IDE·감독·체험 페이지에서 읽은 가이드 해설을 재구성했습니다. 원 PDF를 다시 회수한 것은 아닙니다. 실제 화면·최신 공지가 우선입니다.

## 단계마다 확정되는 것이 다름

| 단계 | 의미 | 다음에 필요한 것 |
| --- | --- | --- |
| 파일 저장 | 작업공간 디스크에 반영 | 필수 경로·충돌·실행법 파악 |
| 제출 미리보기 | 제출 후보 일부를 화면에서 확인 | 전체 파일 목록으로 단정하지 않기 |
| 제출물 확정 | 후속 질문의 기준이 될 파일이 고정 | 이후 코드 수정 반영을 가정하지 않기 |
| 질문 생성 대기 | 작업 기록 기반 문항 준비 | 과제 시간 추가로 쓰지 않기 |
| 후속 직접 답변 | 자신의 결과를 직접 설명 | AI·복사 붙여넣기 없이 안내대로 입력 |
| 최종 완료 | 응시 종료 표시 | 제출 ID·시각·파일 수·크기 등 제공 확인 정보 읽기 |

Notion의 가이드 해설에 따르면 첫 질문은 '문제 풀기' 선택부터, 다음 질문은 직전 답 제출부터 타이머가 시작되고 이전 답변으로 돌아갈 수 없습니다. 문항 만료나 전체 종료 때의 처리도 실제 공지를 따릅니다. 준비한 6개 연습 질문이 실제 질문 순서라고 가정하지 않습니다.

**전체 종료 시각은 과제·대기·후속을 모두 포함합니다.** 작업 180분, 질문 대기, 후속 30분을 관리하며 종료 약 10분 전 제출 준비라는 권고를 '일찍 파일만 확정하면 최종 완료'로 오해하지 않습니다.

## 무엇을 저장할까

실제 README가 요구한 파일과 경로를 따릅니다. 이 키트의 양식 이름은 필수 제출 명세가 아닙니다. 임시 파일·실패한 출력·키트 참고 폴더가 제출 대상으로 들어가는지도 실제 지시에 따라 판단합니다. 원자료를 임의로 지우거나 재작성하지 않습니다.

## 감독·장비에서 헷갈리는 두 QR

Notion은 앱 설치 QR과 응시 연결 QR을 구분합니다. 설치는 공식 경로로, 연결은 Proctor 앱에서 해당 응시 화면의 QR을 스캔하는 절차라고 설명합니다. 실제 UI 순서가 우선이며 에이전트가 대신 클릭하지 않습니다.

전면 카메라 구도·신분증 가림·안경 검사 등은 공식 촬영 지시를 따릅니다. 개인 문서와 감독 화면을 이 저장소에 올리지 않습니다. 기존 권장 기기 사양을 최신 필수 사양이라고 바꾸지 않습니다.

## 오류가 났다면

1. 발생 시각과 현재 단계, 직전 행동을 구분합니다.
2. 저장·터미널·AI·Browser·감독 중 어느 영역인지 좁힙니다.
3. 제공된 해당 영역 재연결/공식 복구 절차를 따릅니다. 저장 충돌의 양쪽 내용을 보존합니다.
4. 플랫폼·감독 오류는 공식 문의에 증상을 접수합니다.
5. 접수·복구 시도·복구 확인·시험 종료를 다른 상태로 남깁니다.

같은 개인 링크 재접속 시 저장 기준으로 이어진다는 Notion 해설이 있으나 시간 정지·마감 연장을 뜻하지 않습니다. 질문 대기 지연, 본인 과도한 프로세스의 OOM도 구제 보장으로 해석하지 않습니다.
