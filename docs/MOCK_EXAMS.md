# 통합 모의 5종: 질문부터 설명까지

Notion 10번의 방문 신청·고객지원·데이터 합계 수리 모의를 실제 연습 파일로 구체화했고, 시간 제한 과제에서 자주 필요한 판단(구체 질문, 역할 분리, 정제·최적화, 비용)을 D로, 배정이 아닌 적재·묶음 유형을 E로 추가했습니다. **전부 자체 합성 문제이며 기출·예상 답안·공식 채점표가 아닙니다.** A~E 전체 모의의 완성 구현·실행·검증은 NOT_RUN입니다. 별도의 작은 도구 연결 예제는 [합성 연결 검증 기록](METHOD_TRACE_VALIDATION.md)으로 구분합니다. 사용자도 직접 수행한 뒤에만 진도를 기록합니다.

| 모의 | 연습할 판단 | 시작 파일 |
| --- | --- | --- |
| A 방문 신청 | 규정 충돌·누락·중복·판정 이유 | [의뢰](../exercises/visitor-review/BRIEF.md) |
| B 고객 문의 | 범주·우선순위·사람 검토·오분류 비용·주입된 지시 | [의뢰](../exercises/support-triage/BRIEF.md) |

## 진행 순서

1. BRIEF만 읽고 문제 카드·첫 질문·필수 범위를 작성합니다.
2. FACILITATOR를 진행자가 답변하는 자료로 쓰거나, 혼자라면 먼저 질문한 부분부터 읽습니다.
3. 요구가 바뀐 이유를 [연결표](../templates/REQUIREMENT_TRACEABILITY.md)에 적습니다.
4. 제공된 기존 런타임에서 작은 결과물을 구현합니다. 현재 검사 정책을 지킵니다.
5. 실제 관측과 NOT_RUN, 한계를 기록하고 제출 후보 파일을 정리합니다.
6. 사전 연습 환경에서만 [6개×5분 직접 설명](NO_AI_REHEARSAL.md)을 수행합니다.

## 180분 모의 배분 예시

0~15분 읽기 / 15~35분 질문·기준 / 35~105분 첫 구현 / 105~145분 허용 검사·오류 수정 / 145~165분 필수 보완 / 165~170분 설명 정리 / 170~180분 저장·제출. 자체 제안이고 실제 대회의 공식 단계별 배분이 아닙니다. 후속 설명 시간은 별도로 둡니다.

## 평가할 것

요구를 정확히 파악했는가? 답변으로 구현이 바뀌었는가? 필수 기능이 끝까지 이어지는가? 관측한 입력과 결과가 있는가? 미검증·한계를 말하는가? 선택한 구조를 직접 설명하는가?

Notion의 35/35/30은 자체 연습 가중치였으며 공식 배점이 아닙니다. 여기서는 숫자 점수를 자동으로 주지 않습니다. 미실시·미검증 항목에 점수를 채우지 않습니다.

## 연습 기록

회차·실측 시간 / 질문과 답 / 선택한 최소 범위 / 실제 수정 파일 / 허용 검사와 결과 또는 NOT_RUN / 남은 한계 / 직접 설명 여부 / 다음 취약점 한 가지. 연습 파일·답안을 실제 시험의 정답으로 반입하지 않습니다.
