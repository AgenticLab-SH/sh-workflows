# 단계별 Codex 지시문

제공된 환경에서 허용된 작업에 쓰는 빈 틀입니다. 실제 과제 내용·파일·규칙으로 채웁니다. 현재 시스템·모델·검사 정책이 우선이며, 이 지시문은 검사를 새로 허가하지 않습니다.

## A. 처음 읽기

    실제 과제 루트는 [경로], 참고 키트는 [경로]다.
    README와 허용된 저장 파일을 읽고 사용자·목표·자료·필수 출력·
    금지 사항·불명확한 조건을 구분해라.
    이미 적힌 사실은 재질문하지 말고, 구현을 바꿀 질문부터 제시해라.
    이 단계에서는 코드·설정·의존성을 변경하지 마라.

## B. 담당자 답변 반영

    담당자가 확인한 사실은 [답변]이다.
    기존 가정 [가정] 중 달라진 부분만 갱신해라.
    확정 규칙과 아직 답이 없는 규칙을 구분하고,
    바뀌는 입력·분기·출력·기대 사례를 짧게 정리해라.
    담당자에게 코딩 방법의 정답을 요구하지 마라.

## C. 첫 작은 구현

    필수 기능 [A]를 먼저 구현한다.
    입력은 [파일], 규칙은 [확정 근거], 출력은 [형식·경로]다.
    변경 범위는 [파일/모듈], 원본 자료는 보존한다.
    제외 기능은 [이유와 목록]이다.
    작업 후 실제 수정 파일과 현재 상태를 보고하고,
    허용되지 않았거나 실행하지 않은 검사는 NOT_RUN으로 적어라.

## D. 관측한 실패

    입력: [실제 입력]
    기대: [확정 규칙에 따른 결과]
    실제: [관측한 값·오류]
    근거: [명령/파일/수동 동작과 시각]
    해당 차이의 원인을 필요한 코드·로그에서 좁혀라.
    [허용 범위] 안에서 수정하고 현재 정책상 허용된 검사만 수행해라.
    실행하지 못한 사례와 다른 기능에 미칠 영향은 구분해 보고해라.

## E. 읽을 수 없는 화면·저장 충돌

    에디터 화면과 미저장 버퍼를 볼 수 있다고 가정하지 마라.
    허용된 실제 저장 파일과 마지막 관측을 기준으로 차이를 정리해라.
    저장 충돌이 있으면 양쪽 변경을 덮어쓰지 말고 선택 지점을 알려줘.
    Browser는 내가 직접 조작한다. 기대 동작과 확인할 입력만 설명해라.
    수동 결과를 전달받기 전에는 화면 검증 완료라고 쓰지 마라.

## F. 제출 준비

    README가 요구한 산출물과 경로에 맞춰 현재 파일을 정리해라.
    필수 요구별 구현 위치·관측 근거·NOT_RUN·남은 한계를 연결해라.
    차용한 공개 자료와 선택 이유를 적고 불필요한 새 기능은 추가하지 마라.
    제출 확정과 최종 완료는 내가 공식 화면에서 직접 진행한다.
    실제 AI 금지 후속 단계가 시작되면 답안·메모를 만들거나 도구를 쓰지 마라.

## G. 시간 부족

    남은 [분] 안에 반드시 필요한 결과는 [필수]다.
    현재 하고 있는 일 중 제출에 필요 없는 확장을 멈추고,
    가능한 최소 기능·막힌 부분·제출 준비를 우선순위로 다시 정리해라.
    기능/도구 하나가 안 된다는 이유로 허용된 다른 일을 모두 멈추지 마라.
    미완료를 완료로 보고하지 마라.

## 지시 상태의 구분

'전송됨 / 승인 대기 / 실행 중 / 응답 완료 / 산출물 관측 / 제출 완료'는 서로 다릅니다. 실행 중인 동일 요청을 반복하지 않습니다. 실제 발신 여부가 불명확하면 원 상태를 먼저 확인합니다. 단순 파일 경로 오타는 필요한 범위에서 고치되, 실제 권한 거절을 다른 계정·도구로 우회하지 않습니다.
