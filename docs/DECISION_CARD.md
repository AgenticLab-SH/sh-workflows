# 한 페이지 의사결정 카드
최신 공식 규칙 우선. 제공 Codex만 사용·업데이트 금지. 시험 중 Push·외부 AI/전송·캡처·GUI 자동화 금지. AI 금지 후속 단계에는 도구와 Skill 사용을 중단한다.

| 단계 | 스스로 확인할 질문 | 짧게 남길 근거 |
| --- | --- | --- |
| 시작 ⑨ | 누구의 어떤 문제? 필수·제약·산출물·제외·완료 기준은? | 목표와 작은 설계, 핵심 테스트. 허용 시 오버라이드 반영을 새 세션에서 확인 |
| 질문 ④⑤ | 다음 2~3개 답이 설계를 바꾸나? 이미 들은 내용인가? 구체 질문만 답하는 무제한 담당자 에이전트면 애매한 점을 전부 원장에 올렸나? | 사실/경험/규정/가설/충돌/미확정 → 바뀐 결정 |
| 설계 ①②③ | 유지·수정·조합·재설계 중 무엇이 가장 단순한가? 역할이 둘 이상이면 역할 매트릭스를 채웠나? | 검증된 패턴, 적용 조건, 업무 예외 |
| 비용 ①⑥ | 일회성인가 반복인가? 사람 검토·개발·운영까지 절감되나? | 가정/실측 구분한 ROI. 기능마다 AI 사용 비용 한 줄 |
| 구현 ⑥⑧ | 이번 작은 위임의 완료 기준은? 불필요한 DB·Agent를 붙였나? 최적화라면 정식화 카드와 기준선이 먼저 있나? | 사용자 목표 → 작은 위임 → 결과 → 다음 판단 |
| 검증 ⑦⑧ | 정상·경계·누락/충돌에서 실제 실행했나? | 명령·기대·실제, PASS/FAIL/NOT_RUN/BLOCKED |
| 이해 ⑦⑨ | 요구→파일/함수→입출력→설계 이유→테스트→한계를 설명하나? | 자기 말로 30초 설명 |
| 제출 ⑩ | 저장됐나? 참고 키트가 섞이지 않았나? 공식 완료 표시를 봤나? | Browser·제출은 본인 수동 확인 |

ROI(분) = 반복횟수 × (기존 시간 - 자동 시간 - 검토 시간) - 개발·검증 - 운영.
필수 승인·안전은 절감 계산으로 없애지 않는다.
질문을 멈출 기준: 핵심 업무 규칙과 정상/예외 완료 사례가 충분하면 구현한다.
과잉설계 판단: 요구에 필요한가 → 위험을 줄이나 → 더 간단한 방법은 → 검증 가능한가.

Technique / Intent / Cognition: 작동 결과 / 내가 지휘한 이유 / 내가 이해하고 설명함.
이는 일반 제품 평가 관점이며 SK하이닉스 공식 세부 배점표가 아니다.
