# 근거로 판단하고 오류를 좁히기

이 문서는 검사 실행 권한을 부여하지 않습니다. 현재 모델·플랫폼에서 금지된 검사는 실행·위임하지 않고 NOT_RUN으로 남깁니다. 허용된 검사에 한해 다음 사고 순서를 적용합니다.

## 0~4의 근거 수준

| 수준 | 실제로 아는 것 | 과장하면 안 되는 주장 |
| --- | --- | --- |
| 0 | AI의 완료 보고 | 구현·실행 완료 |
| 1 | 저장 파일과 그 내용 | 정상 작동 |
| 2 | 해당 명령 종료·응답 또는 특정 화면 | 업무 규칙 전체 정확 |
| 3 | 정한 입력의 기대/실제 일치 | 모든 입력·화면 통과 |
| 4 | 수정 후 같은 실패 사례와 관련 회귀의 관측 | 검사하지 않은 동작의 무결성 |

실제 파일과 AI 보고만 받은 파일, 참가자가 직접 본 화면, 기대만 적은 사례를 따로 표시합니다. '코드가 있음 → 실행됨 → 요구가 맞음'은 다른 증거입니다.

## 정상·경계·누락·충돌·회귀

합성 규칙이 최대 4명이라면 3명은 정상, 4/5명은 경계, 빈값은 누락, 상충 중복은 충돌, 수정 후 3명의 기존 결과는 회귀 사례입니다. 실제 업무 규칙을 확인한 뒤 기대값을 정합니다.

**실행 전 예상과 실행 후 관측을 같은 열에 쓰지 않습니다.** 날짜·중복·규정이 미정이라면 기대 결과도 미정 또는 담당자 확인 대기일 수 있습니다.

## 실패 기록의 최소 단위

입력 → 기대와 근거 → 실제 값/오류 → 명령·파일·수동 행동 → 원인 근거 → 수정 범위 → 허용된 재관측/NOT_RUN → 남은 한계.

예시 로그는 연습 자료이지 실제 성공 기록이 아닙니다. 코드 한 줄을 바꿨다는 사실만으로 원인이 증명되는 것도 아닙니다.

## 증상별로 먼저 나눌 것

| 증상 | 필요한 구분 | 피할 판단 |
| --- | --- | --- |
| npm test가 없음 | 실행 스크립트 존재 여부 | 앱 로직의 실패라고 단정 |
| HTTP 200인데 버튼 오류 | 서버 응답과 UI 상태·사용자 흐름 | 화면 전체 통과라고 기록 |
| Browser가 비어 있음 | 서버·실제 포트·바인딩·경로 | 원인 확인 없이 전면 재작성 |
| Codex가 멈춘 듯함 | 승인 대기·실행 중·응답 완료·도구 오류 | 같은 요청을 반복 발신 |
| 에디터와 파일이 다름 | 미저장 버퍼·외부 변경·실제 디스크 | 한쪽을 임의 덮어쓰기 |
| git diff가 비어 있음 | 미추적 파일·다른 루트·Git 여부 | 수정·신규 파일이 전혀 없다고 단정 |
| 모델/플랫폼 오류 | 응용 코드 오류와 운영 장애 | 다른 계정·외부 AI로 우회 |
| 메모리 부족 | 본인이 만든 프로세스와 작업량 | 다른 작업을 일괄 종료하거나 구제 보장 추정 |

## U/M과 저장 상태

Git의 U는 미추적, M은 수정 상태일 수 있습니다. 에디터 제품의 표시는 다를 수 있습니다. 이 글자만으로 '미저장 버퍼'를 확정하지 않습니다. 제공 UI의 저장 상태와 실제 저장 파일이 근거입니다.

## 어디까지 복구할까

파일을 보기 위한 문제라면 저장·탐색기·해당 터미널 영역부터 확인합니다. 플랫폼 문제는 공식 문의에 시각·단계·직전 동작·증상을 보냅니다. 문의가 접수됐다는 사실은 시간 연장이나 추가 체험을 뜻하지 않습니다.

[장애 보고 양식](../templates/INCIDENT_REPORT.md)과 [실행 근거 양식](../templates/EVIDENCE.md)을 사용합니다. 원자료·로그인·다른 프로세스를 지키고, 모르는 상태를 0이나 완료로 바꾸지 않습니다.
