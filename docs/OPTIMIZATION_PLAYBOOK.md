# 최적화 운영서: 프로파일링 → 정제 → 정식화 → 알고리즘 비교 → 선택 → 검증

데이터를 가공하고 최적화 알고리즘을 스스로 골라 적용해야 하는 과제에서 쓰는 운영서다. 공식 규칙·과제 지시가 이 문서보다 우선한다. 목적·제약·가중치·정제 기준은 참가자와 업무 담당자가 정한다. `tools/opt_kit.py`는 기준선과 소규모 검증을 위한 범용 구성 요소이며 완성 답안이 아니다. 예시는 모두 합성 영역이다.

짧은 흐름만 필요하면 `.agents/skills/optimization-modeling/SKILL.md`를 쓴다.

## 1. 결정 흐름: 질문 몇 개로 유형 판별

차례로 답하고 처음 "예"가 나온 줄의 유형부터 본다. 여러 유형이 섞이면 주 결정 하나를 먼저 풀고 나머지는 제약이나 후처리로 둔다.

1. 항목마다 **어느 대상에 넣을지**를 정하나? (수강생→강좌, 작업→담당자) → 배정·매칭. 대상에 정원이 있으면 정원 있는 배정.
2. 후보 중 **일부만 고르고** 예산·용량 합계 제한이 있나? → 선택·예산(배낭).
3. 크기가 있는 항목을 **최소 개수의 용기**에 나눠 담나? → 적재·묶음(bin packing).
4. **시간 구간**이 겹치면 안 되거나 마감·우선순위로 처리 순서를 정하나? → 일정·구간.
5. 모든 지점·작업을 한 번씩 거치는 **순서**를 정하고 이동·전환 비용 합을 줄이나? → 방문·작업 순서.
6. 작업 단계 그래프에서 시작 단계부터 완료 단계까지 **최소 비용 연결** 하나가 필요한가? → 최단 경로.
7. 비슷한 것끼리 **묶음**을 만들고 묶음 크기 제한이 있나? → 군집·묶기.
8. 서로 충돌하는 목표가 **둘 이상**인가? → 다목적(가중합·사전식·파레토).

그다음 두 가지를 확인한다. 실제 입력 규모(n, m)는 얼마인가? 허용 응답 시간은 몇 초인가?

## 2. 유형별 알고리즘 표

| 유형 | 방법 | 복잡도 | 적정 규모(표준 Python 기준 대략) | 장점 | 단점 | `tools/opt_kit.py` |
|---|---|---|---|---|---|---|
| 배정 1:1 | 헝가리안 | O(n²m) | n·m ≤ 수백 | 정확해, 결정적 | 정원·추가 제약 표현 불가 | `hungarian` |
| 배정 정원 | 열 복제 + 헝가리안(미배정 더미·금지 칸 선택) | O(n²·슬롯) | 행×슬롯 ≤ 수만 | 정원 있는 정확해, 정원 부족도 처리 | 복제로 크기 증가, 행당 1개만 | `hungarian_with_capacity` |
| 배정 정원 | 탐욕 → 교환 개선 | 탐욕 O(nm log nm), 교환 라운드당 O(n²+nm) | 수천 행 | 빠르고 설명 쉬움 | 최적 보장 없음, 교환은 모든 행 배정 가정 | `greedy_assign_with_capacity`, `improve_assignment_by_swap` |
| 배정 행당 여러 개·그룹 제약 | 최소비용 유량 | 증가 경로마다 O(V·E) | 행×열 ≤ 수천 쌍 | 행당 k개, (행, 그룹)당 1개, 정원, 미배정을 함께 정확히 | 큰 입력은 시간 측정 필요 | `assignment_flow`, `min_cost_flow` |
| 배정 검증 | 완전탐색(가지치기) | O(mⁿ) | 행 ≤ 12, 열ⁿ ≤ 200만(6열이면 8행까지) | 작은 표본의 기준 정답 | 큰 입력 불가, 행당 1개만 | `brute_force_assignment` |
| 제약 검사 | 정원·행당 개수·그룹 위반 목록 | O(배정 수) | 제한 없음 | 위반 0건 확인 | 금지 칸은 직접 확인 | `constraint_report` |
| 선택·예산 | 비율 탐욕 | O(n log n) | 제한 없음 | 단순 | 최적 보장 없음 | `greedy_knapsack` |
| 선택·예산 | 0/1 배낭 DP | O(n·예산) | n×예산 ≤ 500만 | 정확해 | 정수 단위 필요(예: 천 원 단위로 환산) | `knapsack_01` |
| 적재·묶음 | FFD | O(n·상자 수) | 수천 | 단순, 최적의 약 11/9배 이내 | 추가 제약 표현 어려움 | `first_fit_decreasing` |
| 적재·묶음(여러 한도·함께 담기 금지) | 순서 지정 첫 맞춤 → 넣는 순서를 바꾸는 담금질 | 순서 1회 O(n·상자 수·차원) | 수백 | 무게·부피 같은 여러 한도와 라벨 충돌을 함께 지킴, 하한과 비교 가능 | 기준선은 최적 보장 없음, 담금질은 seed 필요 | `first_fit_multi`, `bins_lower_bound`, `pack_report`, `simulated_annealing` |
| 일정·구간 | 끝 빠른 순 선택 | O(n log n) | 제한 없음 | 겹침 없는 최대 개수의 정확해 | 가중치 있는 경우는 별도 DP | `interval_schedule` |
| 일정 | 우선순위 규칙(마감 순, 짧은 작업 순) | O(n log n) | 제한 없음 | 설명 쉬움 | 목적별로 규칙이 다름 | 직접 정렬 |
| 방문·작업 순서 | 최근접 이웃 | O(n²) | 수천 | 빠른 기준선 | 흔히 10~25% 나쁨 | `nearest_neighbor_order` |
| 방문·작업 순서 | 2-opt | 라운드당 O(n²) | 수백 | 단순하고 개선 큼 | 국소 최적 | `two_opt`, `order_length` |
| 방문·작업 순서 | 완전탐색 | O(n!) | n ≤ 9 | 정확해 | 큰 입력 불가 | `brute_force_order` |
| 최단 경로 | 다익스트라 | O((V+E) log V) | 수십만 간선 | 정확해 | 음수 간선 불가 | `dijkstra`, `shortest_path` |
| 군집·묶기 | 용량 고려 탐욕, 간단 k-means | O(nk·반복) | 수천 | 단순 | 초기값 의존, seed 필요 | 없음(직접 작성) |
| 범용 개선 | 담금질(simulated annealing) | 반복 수 × 비용 계산 | 시간 제한 안 | 거의 모든 문제에 적용 | 매개변수 조정, seed 필요 | `simulated_annealing` |
| 다목적 | 가중합 / 사전식 / 파레토 | 후보 수에 비례 | 후보 수천 | 선택지를 담당자에게 보여 줌 | 가중치는 업무 결정 | `pareto_front` |

외부 라이브러리(scipy의 `linear_sum_assignment`, ortools, pulp, networkx)는 **이미 설치·허용된 경우에만** 고른다. 설치 여부는 `python -c "import scipy"`처럼 읽기만 확인한다. 설치 명령을 실행하지 않는다. 설치 불가 환경에서는 위 표준 라이브러리 함수나 직접 작성한 작은 함수로 대신하고, 그 사실을 설명에 적는다.

`python tools/opt_kit.py demo`는 내장 합성 예제(문화센터 강좌 배정, 정원 부족·시간대 제약이 있는 강좌 배정, 예산 내 항목 선택, 작업 순서)로 기준선 → 개선 → 정확해 비교 결과를 JSON으로 보여 준다. 과제 폴더 안에 키트를 복제했다면 `python3 .hackathon-kit/tools/opt_kit.py demo`처럼 키트 위치에 맞게 바꾼다.

### 배정 제약을 모델링하는 법

정원 합이 행 수보다 작으면 `hungarian_with_capacity(costs, caps, allow_unassigned=True, unassigned_cost=u)`를 쓴다. 행마다 비용 u인 더미 열을 붙인 것과 같고 미배정 행은 `None`이 된다. u는 "비워 두는 것"의 비용이라 담당자가 정할 값이다. `allow_unassigned=True`이면 `unassigned_cost`를 반드시 적어야 한다(빼면 `InputError`). 함정이 있기 때문이다. 0 이상인 불만족 비용을 최소화하면서 u=0을 두면 모든 행에서 "비워 둠"이 가장 싸므로 아무도 배정되지 않는다. u는 받아들일 수 있는 가장 큰 비용보다 크게 잡는다. 점수를 음수 비용으로 바꿔 최대화할 때는 u=0이 "비면 0점"이라 자연스럽다. `greedy_assign_with_capacity`도 같은 규칙이다. 미배정 행(`None`)이 섞인 탐욕 결과는 `improve_assignment_by_swap`에 그대로 넣을 수 없다. 미배정 행을 배정·비용 행렬에서 빼고 넘기거나, 처음부터 `assignment_flow`로 정확히 푼다. 배정하면 안 되는 칸은 `forbidden={(행, 열), ...}`로 넘긴다. 이 칸은 결과에 절대 쓰이지 않고, 모든 행을 배정해야 하는데 불가능하면 `InputError`가 난다. 큰 비용(예: 1e6)을 직접 넣는 방식은 그 값이 충분히 크지 않으면 금지 칸이 쓰이므로 결과에서 따로 센다. 점수를 최대화하려면 점수에 −1을 곱한 비용을 최소화한다(`assignment_flow`는 `maximize=True`). 한 행이 최대 k개를 받고, 같은 그룹(예: 같은 시간대) 열은 행마다 하나만 받으며, 열마다 정원이 있으면 헝가리안 행렬로는 행당 k개를 표현할 수 없다. 이때는 `assignment_flow(scores, k, caps, groups=시간대, maximize=True)`로 최소비용 유량을 정확히 푼다. 내부 구조는 출발 → 행(용량 k) → (행, 그룹)(용량 1) → 열(용량 1) → 도착(용량 = 정원)이고, 빈 자리는 행 → 도착 우회 간선으로 처리한다. 결과는 `constraint_report(assignment, caps, row_limits=k, groups=시간대)`로 위반 0건을 확인한다.

미리 확정된 배정(고정 배정)이 있으면 풀기 전에 사전 처리한다. 고정 배정 (행, 열)마다 ① 그 열의 정원을 1 줄이고, ② 그 행의 한도를 1 줄이고, ③ 같은 그룹(예: 같은 시간대)의 열을 그 행에 모두 금지하고, ④ 고정 배정의 점수는 따로 합산해 마지막에 더한다. 사전 처리 뒤 정원이나 한도가 음수가 되면 해가 없으므로 풀지 말고, 어느 열·행이 몇 개 넘쳤는지 충돌 목록으로 만들어 담당자에게 보고한다. `assignment_flow(..., fixed=[(행, 열), ...])`가 같은 절차를 안에서 수행한다. 결과의 `assignment`에는 고정 배정이 포함되고 `fixed_total`에 고정 배정 점수가 따로 나온다. 정원·한도 초과, 같은 행의 같은 그룹 고정 배정, 금지 칸 고정, 중복 고정이 있으면 풀지 않고 `assignment=None`과 `conflicts` 목록을 돌려준다. 오류로 멈추지 않고 목록을 주므로 충돌을 한 번에 모아 질문할 수 있다.

사전식 동점 처리(1순위 비용이 같으면 보조 키가 작은 쪽)는 "점수×1000"처럼 임의 큰 가중치를 곱하지 않는다. 1순위 비용을 정수로 만들고 보조 키(0 이상 정수, 예: 신청 순번)를 작은 단위 ε로 더한다. 조건은 ε × (보조 키 합의 최댓값) < 1순위 비용의 최소 차이(정수면 1)다. 점수를 최대화할 때(`maximize=True`)는 부호가 반대다. 보조 키가 작은 쪽이 이기려면 점수에서 ε × 보조 키를 **뺀다**(점수 − ε × 보조 키). 더하면 보조 키가 큰 쪽이 이긴다. 소수 오차가 걱정되면 양쪽에 같은 정수 배율을 곱한다. 한계도 있다. 이 방법은 보조 키의 **합**을 줄일 뿐이라 특정 두 사람 사이의 순서 역전이 0건이라고 보장하지 않는다. 단계가 셋 이상이면 배율이 커져 오차가 늘어난다. 엄격한 사전식이 필요하면 1순위 최적값을 구한 뒤 그 값을 제약으로 고정하고 2순위를 다시 푸는 방식을 검토한다.

## 3. 선택 기준

| 기준 | 질문 |
|---|---|
| 규모 | 실제 n에서 정확해가 시간 안에 끝나나? |
| 시간 제한 | 응답 몇 초 안에 끝나야 하나? |
| 설명 가능성 | 담당자에게 한두 문장으로 설명되나? |
| 결정성 | 같은 입력에 같은 결과가 나오나? 난수면 seed가 고정됐나? |
| 구현 시간 | 남은 시간 안에 만들고 검증할 수 있나? |
| 검증 용이성 | 작은 표본에서 정확해와 비교할 수 있나? |

기본값: **단순 기준선 먼저 → 개선 → 소규모에서 정확해와 비교**. 기준선이 요구를 이미 만족하면 거기서 멈춘다.

## 4. 정식화 카드 예

### 예 1. 문화센터 강좌 배정

| 항목 | 내용 |
|---|---|
| 결정 변수 | 수강생 i(120명)를 강좌 j(6개) 중 하나에 배정 |
| 목적 | 불만족 비용 합 최소. 비용 = 희망 순위(1순위 0, 2순위 1, 3순위 3, 미희망 10). 순위별 값은 담당자 확인 필요 |
| 하드 제약 | 강좌 정원(각 20~25명), 수강생당 정확히 한 강좌, 참석 불가 시간대 강좌 배정 금지 |
| 소프트 제약 | 같은 동호회 회원이 한 강좌에 몰리지 않게(동호회당 강좌별 5명 초과분 1명당 벌점 2) |
| 규모·시간 | 120×6, 1초 이내 |
| 동점 처리 | 같은 비용이면 수강생 번호 오름차순으로 먼저 배정 |
| 후보 | 정원 탐욕 → 교환 개선 / 열 복제 헝가리안(120×150 슬롯, 정확해, 참석 불가 칸은 `forbidden`). 동호회 벌점이 들어가면 헝가리안만으로는 표현 불가 → 헝가리안 결과를 시작점으로 교환 개선 |
| 검증 | 정원 위반 0, 불가 시간대 0, 1순위 비율, 기준선 대비 비용. 정확해 비교는 8명 이하 표본에서 `brute_force_assignment`(6⁸ ≈ 168만 조합으로 도구 한도 200만 이내), 전체 120명은 `hungarian_with_capacity` 또는 `assignment_flow` |

### 예 2. 창고 상자 적재

| 항목 | 내용 |
|---|---|
| 결정 변수 | 물품 i(300개)를 어느 상자에 넣을지 |
| 목적 | 사용 상자 수 최소. 동률이면 마지막 상자의 남는 공간 최대(사전식) |
| 하드 제약 | 상자당 부피 ≤ 60L, 무게 ≤ 20kg, 액체와 분말은 같은 상자 금지 |
| 소프트 제약 | 같은 주문의 물품은 가능한 한 같은 상자(분리 1회당 벌점 1) |
| 규모·시간 | 300개, 2초 이내 |
| 정제 질문 | "부피가 mL와 L로 섞여 있습니다. 1,000 미만 값을 L로 봐도 될까요?" |
| 후보 | 부피 기준 FFD(기준선) → 무게·금지 조합을 넣은 FFD 변형 → 담금질로 상자 비우기 시도 |
| 검증 | 각 상자 부피·무게 이하, 금지 조합 0, 하한 ceil(총부피/60)과 상자 수 비교 |

## 5. 정제 로그 형식

원본은 그대로 두고 변환 규칙마다 한 줄씩 남긴다.

| 순번 | 규칙 | 근거(결정/가정) | 대상 열 | 영향 행 | 전 → 후 행 수 |
|---|---|---|---|---|---|
| 1 | 앞뒤 공백 제거 | 결정(형식 정리) | name, dept | 14 | 300 → 300 |
| 2 | (name, dept) 같으면 중복으로 보고 첫 행 유지 | 가정 → 담당자 확인 대기 | name, dept | 3 | 300 → 297 |
| 3 | 소요시간 '시간' 단위를 분으로 환산 | 결정(담당자 답변 2026-xx-xx) | duration | 21 | 297 → 297 |
| 4 | 소요시간 결측 행 제외 | 가정 | duration | 2 | 297 → 295 |

담당자 질문은 질문 하나에 사실 하나·물음표 하나로 쓰고, "어떻게 할까요" 같은 열린 표현 대신 예/아니오·수치·선택지로 답할 수 있게 한다. 영향 건수는 질문 앞 맥락 문장에 둔다. 사람 담당자에게는 2~3개씩, 구체 질문에만 답하는 무제한 담당자 에이전트에게는 질문 하나에 사실 하나로 모두 묻고, 전송 단위는 반응을 보고 정한다. 예:

- "소요시간 결측은 2/297행입니다. 결측 2건은 분석에서 제외해도 되나요?"
- "두 방법의 비용 차이는 약 1%입니다. 결측 2건은 (a) 제외, (b) 같은 유형 중앙값 45분으로 채움 중 어느 쪽인가요?"

## 6. 검증 보고 형식

```text
문제 유형: 정원 있는 배정 (120×6)
기준선: 정원 탐욕, 목적값 142
선택안: 탐욕 + 교환 개선, 목적값 118 (기준선 대비 -16.9%)
하드 제약 위반: 정원 0, 불가 시간대 0
정확해 비교: 8명 표본 5개에서 gap 0, 0, 1, 0, 0 / 전체 입력은 열 복제 헝가리안 116 (gap 2)
실행 시간: 0.08초 (실제 규모, 3회 측정 중 최대)
seed 안정성: 해당 없음(결정적) / 담금질이면 seed 1~5의 최소·최대
역할별 지표: 1순위 배정 비율 71%, 강좌별 인원 편차 최대 3명
가정: 미희망 비용 10(담당자 확인 대기), 동점 시 수강생 번호 순
한계: 교환 개선은 국소 최적이며 동호회 벌점을 바꾸면 결과가 달라질 수 있음
NOT_RUN: 실제 대규모 입력의 정확해 비교
```

숫자는 실제 실행 출력에서 옮긴다. 위 숫자는 형식 예시다.

## 7. 흔한 실수

- **데이터를 LLM이 눈으로 계산**: 합계·건수·최적값을 대화 중 암산하지 않는다. 코드로 계산하고 출력값을 인용한다.
- **제약을 목적에 섞음**: 정원 같은 하드 제약을 작은 벌점으로만 넣으면 위반 해가 나온다. 하드 제약은 구조로 막거나 큰 벌점과 함께 위반 건수를 따로 센다.
- **기준선 없이 '최적'이라 주장**: 탐욕 기준선 값과 작은 표본의 정확해 없이 개선이나 최적을 말하지 않는다. 휴리스틱 결과는 '개선안'이라고 부른다.
- **난수 seed 미고정**: `random.Random(seed)`를 함수 인자로 받는다. 전역 `random.random()`과 시간 기반 seed를 쓰지 않는다.
- **단위 혼재**: 분/시간, 원/천원, kg/g이 섞이면 목적값이 의미를 잃는다. 프로파일링 단계에서 열별 단위를 확인하고 환산 규칙을 로그에 남긴다.
- **동점 처리 미정**: 같은 비용 후보가 많으면 실행마다 결과가 달라 보일 수 있다. 정렬 키에 식별자를 넣어 고정한다.
- **실제 규모에서 시간 미측정**: 작은 예제로만 확인하고 끝내지 않는다. 실제 크기에서 `time.perf_counter()`로 잰다.
